# NullIME(눌림) 스펙

NullIME(눌림)은 언어 전환이 필요없는 다중 언어 입력기다.

## 사용자 결정 (2026-11-15)

- D1. 대상 환경은 웹 데모, macOS, Windows이다. 그렇기 때문에 엔진과 플랫폼 구현을 구분한다.
- D2. 지원 언어 조합은 QWERTY English + 두벌식 한국어 + Romaji 일본어다.
- D3. 일본어는 한자 변환까지 한다.
- D4. 키를 칠 때마다 가장 확률이 높은 해석을 보여준다. 일본어 IME처럼 조합 창(composition window)이 보인다.
- D5. 확정은 스페이스 또는 엔터로 한다. 현재 후보로 확정한 뒤 그 스페이스·엔터 키도 그대로 입력된다.
- D6. 후보 선택은 화살표 키로 한다.
- D7. 확률 계산은 다양한 실험이 필요하다. 아이디에이션 단계이므로 모든 가능성을 열어둔다.
- D8. 좌우 화살표는 변환 중인 칸(segment)을 탐색한다. 상하 화살표는 후보 목록을 탐색한다.
- D9. 조합 중 백스페이스는 마지막 키 입력의 취소다. 한글에서는 자모 하나 제거와 같다.
- D10. 확정된 텍스트에서의 백스페이스는 입력기가 처리하지 않고 앱에 넘긴다.
- D11. 엔진 언어는 Rust다.
- D12. 사용자 선택 학습(고른 후보를 확률에 반영)은 MVP 밖이다.

## 미정 (placeholder)

- 확률 모델 (D7). 엔진은 교체 가능한 `Scorer` 자리를 두고, MVP는 임시 휴리스틱 scorer로 동작한다.
- 한자 사전 출처 (D7). MVP는 소량의 임시 샘플 사전으로 동작한다.

## 구현 중 내린 기본값 (사용자 확인 전)

구현을 막지 않도록 정한 값이다. 사용자가 바꾸면 이 목록을 고친다.

- 조합에 들어가는 키는 영문자 `a-z`(Shift 포함)뿐이다. 그 밖의 인쇄 가능 문자(숫자, 문장부호)는 현재 조합을 확정한 뒤 앱에 넘긴다. 그래서 일본어 장음 `ー`(`-` 키)는 MVP에서 입력되지 않는다.
- Ctrl·Alt·Cmd 조합키, Escape, Tab 등 엔진이 다루지 않는 키는 현재 조합을 확정한 뒤 앱에 넘긴다.
- 칸 경계는 엔진이 정한다. 사용자가 칸 경계를 늘리거나 줄이는 조작(일본어 IME의 Shift+화살표)은 MVP 밖이다.
- Windows에서는 입력기를 한국어(ko-KR) 입력 프로필 하나로 등록한다.
