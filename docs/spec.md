# NullIME(눌림) 스펙

NullIME(눌림)은 언어 전환이 필요없는 다중 언어 입력기다.

## 사용자 결정 (2026-11-15)

- D1. 대상 환경은 웹 데모, macOS, Windows이다. 그렇기 때문에 엔진과 플랫폼 구현을 구분한다.
- D2. 지원 언어 조합은 QWERTY English + 두벌식 한국어 + Romaji 일본어다.
- D3. 일본어는 한자 변환까지 한다.
- D4. 키를 칠 때마다 가장 확률이 높은 해석을 보여준다. 일본어 IME처럼 조합 창(composition window)이 보인다.
- D5. 확정은 스페이스 또는 엔터로 한다. 현재 후보로 확정한 뒤 그 스페이스·엔터 키도 그대로 입력된다.
- D6. 후보 선택은 화살표 키로 한다.
- D7. 확률 계산은 다양한 실험이 필요하다. 아이디에이션 단계이므로 모든 가능성을 열어둔다.
- D8. 좌우 화살표는 변환 중인 칸(segment)을 탐색한다. 상하 화살표는 후보 목록을 탐색한다.
- D9. 조합 중 백스페이스는 마지막 키 입력의 취소다. 한글에서는 자모 하나 제거와 같다.
- D10. 확정된 텍스트에서의 백스페이스는 입력기가 처리하지 않고 앱에 넘긴다.
- D11. 엔진 언어는 Rust다.
- D12. 사용자 선택 학습(고른 후보를 확률에 반영)은 MVP 밖이다.
- D13. 숫자와 문장부호도 조합에 포함한다. 모든 언어 해석에서 그 문자를 그대로(passthrough) 출력한다. 예: `0.1mmwjdeh` → `0.1mm정도`.
- D14. macOS 구현은 지금 하지 않는다. 엔진 API를 잘 만들어 두고 나중에 이식한다.
- D15. 한자 사전은 엔진에 넣지 않고 외부 애셋으로 꽂는다(pluggable).
- D16. 일본어 변환 품질 목표는 최소한 Windows 내장 일본어 입력기를 넘는 것이다. 사용자 평가로는 Windows 내장 < Google 입력 도구다.
- D17. 기본 배포 애셋은 퍼미시브 라이선스 데이터만 쓴다. GPL·CC BY-SA 같은 타사 모델은 다운로드 링크만 제공하고, 사용자가 받은 파일을 직접 꽂는다(bring your own file).
- D18. 웹 데모는 기본으로 축소판 사전을 받고, 전체 사전은 사용자가 선택해서 받는다.
- D19. D16 판정은 AJIMEE-Bench와 Mozc 평가셋으로 엔진을 직접 호출해 자동 채점한다. 비교 기준은 MS IME 공개 수치(AJIMEE 59.6%)다. AJIMEE는 라이선스가 불분명해 레포에 넣지 않고 내려받아 쓴다.
- D20. 문맥 모델은 퍼미시브 코퍼스로 직접 학습한 단어 n-gram 통계 LM을 기본으로 싣는다. 신경망 재정렬(zenz 등)은 사용자가 파일을 꽂을 때만 켠다(D17).

## 미정 (placeholder)

- 확률 모델 (D7). 엔진은 교체 가능한 `Scorer` 자리를 두고, MVP는 임시 휴리스틱 scorer로 동작한다.
- 한자 사전 출처 (D7). MVP는 소량의 임시 샘플 사전으로 동작한다.

## 구현 중 내린 기본값 (사용자 확인 전)

구현을 막지 않도록 정한 값이다. 사용자가 바꾸면 이 목록을 고친다.

- Ctrl·Alt·Cmd 조합키, Escape, Tab 등 엔진이 다루지 않는 키는 현재 조합을 확정한 뒤 앱에 넘긴다.
- 칸 경계는 엔진이 정한다. 사용자가 칸 경계를 늘리거나 줄이는 조작(일본어 IME의 Shift+화살표)은 MVP 밖이다.
- Windows에서는 입력기를 한국어(ko-KR) 입력 프로필 하나로 등록한다.
- 상하 화살표 후보 이동은 목록 끝에서 반대쪽 끝으로 돌아간다. 아래 화살표가 다음 후보다. 좌우 화살표 칸 이동은 양 끝에서 멈춘다.
- 일본어 후보는 사전 변환 결과를 변환 비용순으로 먼저 내고, 그 뒤에 히라가나 읽기와 가타카나를 붙인다. 변환 1순위가 바로 조합 창에 보인다.
- 사전에 없는 구간은 히라가나 그대로와 가타카나로 둔다. 비용은 9000 + 글자당 400이고 가타카나는 600을 더 얹는다. 2글자 이상 미등록 구간은 그 자리에서 시작하는 사전 단어가 없을 때만, 최대 8글자까지 만든다.
- 웹 데모의 작은 사전은 Mozc 비용 6000 이하 단어만 남긴다(`--max-cost 6000`, 약 8.1 MiB). 가타카나 표기 단어는 빼지 않는다. 빼면 AJIMEE 1순위 정확도가 36.0%에서 17.5%로 떨어지고 크기는 0.4 MB만 준다.
- 정확도 측정(D19)은 AJIMEE의 `context_text`를 쓰지 않는다. 엔진에 문맥 모델이 아직 없다(D20).
- `nn` 뒤에 모음이 오는 Romaji는 `n` + `n모음`으로 먼저 읽는다. 예: `konnichiha` → こんにちは가 こんいちは보다 앞선다.
- 일본어 장음 `ー`, 구두점 `。`·`、` 변환은 하지 않는다. `-`·`.`·`,`는 D13대로 그대로 나온다.
- 한 칸은 최대 32 키 입력이다. 더 길면 여러 칸으로 나뉜다.
- 고정된 칸이 있으면 마지막 고정 칸까지의 모든 칸을 다시 해석하지 않는다.
